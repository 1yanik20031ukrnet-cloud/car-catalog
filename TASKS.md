## Этап 6 — публикация автомобиля в соцсети, «Pro»-функция (будущее, не начато)

Спланировано через `/grill-me plan` 2026-09-03, уточнено в тот же
день. Идея: карточка автомобиля в админке — единственный источник
данных и для сайта, и для контента в соцсетях, чтобы не вводить одно
и то же дважды. Направление всегда `сайт → соцсети`, никогда наоборот
(кроме Этапа 6.4, и то не сейчас).

**Позиционирование:** это не базовая функция каталога, а «Pro»-слой
поверх основного продукта — то, что отличает платную/расширенную
версию от обычной. Отсюда два требования к реализации, когда до неё
дойдём:
- продукт без неё должен работать ровно так же, как сейчас — салон,
  которому это не нужно (или не оплачено), не должен чувствовать
  разницы: ни лишних полей в форме по умолчанию, ни просевшей
  скорости, ни новых обязательных настроек;
- саму функцию делать по возможности отключаемой/опциональной
  (не обязательно готовым тумблером уже сейчас — просто не завязывать
  на неё намертво остальной каталог).

**Приоритет — вариант БЕЗ API соцсетей.** Этап 6.1 (просто вводные для
поста: текст + ссылка, без публикации) — то, что делаем в первую
очередь, если вообще возьмёмся. Этапы 6.2–6.4 (реальные интеграции с
API Instagram/Telegram/Facebook) — сознательно не приоритет, могут не
понадобиться вовсе, если хватит готового текста для копирования
вручную.

**Ничего из этого не реализовывать сейчас** — здесь только план.
**Перед тем как начинать любую часть этого этапа (даже 6.1) — сначала
напомнить об этом и вместе решить, как лучше делать, не начинать по
своей инициативе.**

- [ ] **Этап 6.1 — генерация текста поста (без публикации через API) — приоритет**
  - Действие в админке у машины — «Подготовить публикацию».
  - Собирает готовый текст из данных машины (марка, модель, год,
    пробег, двигатель, топливо, коробка, цена) + короткое продающее
    описание + ссылка на страницу автомобиля — под Instagram/
    Telegram/Facebook.
  - Можно посмотреть, отредактировать, скопировать вручную —
    публикации через API на этом этапе нет вообще.
- [ ] **Этап 6.2 — публикация в соцсети (интеграции, не приоритет)**
  - Instagram, Facebook, Telegram.
  - В админке у машины — статус по каждому каналу отдельно: «Сайт —
    опубликовано» / «Instagram — не опубликовано» / «Telegram —
    опубликовано» и т.д., плюс действия «Опубликовать в Instagram» /
    «...в Telegram» / «Опубликовать везде».
  - Перед реализацией — отдельно проверить актуальные API,
    разрешения и ограничения каждой площадки. Не обходить
    ограничения соцсетей неофициальными способами.
- [ ] **Этап 6.3 — единое управление статусом (не приоритет)**
  - Статус машины управляет и сайтом, и (где возможно) соцсетями: в
    продаже → в каталоге; зарезервирован → отметка на сайте; продан →
    уходит из каталога/в архив.
  - Для соцсетей — только явные ручные действия, не пытаться
    автоматически удалять/редактировать чужие публикации без
    надёжной поддержки со стороны API площадки.
- [ ] **Этап 6.4 — обратный импорт из соцсетей (не приоритет)**
  - Новый пост в Instagram → система распознаёт данные машины →
    предлагает создать карточку → продавец подтверждает.
  - Только после того, как `сайт → соцсети` (6.1–6.3) уже стабильно
    работает — посты бывают неполными, форматы разные, есть
    ограничения Instagram API, распознавание неоднозначно; сайт
    должен остаться главным источником данных.

**Почему не рушит текущую архитектуру** (проверено, ничего не
менялось ради этого заранее): у `Car` уже есть `get_absolute_url()`
(ссылка на страницу — Этапу 6.1 нужна готовой), уже есть паттерн
`TextChoices` для перечислений (`Status`, `Currency`, `Fuel`...) —
подойдёт и для будущего списка каналов, и уже есть паттерн отдельной
related-модели на `ForeignKey` (`CarImage`, `Booking`) — так же
позже ляжет будущая модель для статусов публикаций по каналам и их
внешних ID, без переделки `Car`. Ничего из этого не создаём сейчас.
