- [x] **Удобная загрузка фото и внешний вид админки** — *Ян*, ветка
  `feature/admin-usability`
  - одно поле, в котором можно выбрать сразу несколько фотографий;
  - поля формы сгруппированы, служебные скрыты;
  - подключена тема `django-unfold` (тёмная, современная, с цветными
    статусами) — согласовано с владельцем;
  - тема всегда тёмная (без белого светлого варианта), акцентный цвет
    приглушённый серо-синий вместо ярко-фиолетового;
  - ошибки в форме подсвечиваются на самом поле, введённый текст не
    стирается — сбрасываются только выбранные файлы фото (так себя
    ведёт браузер, это не чинится на стороне сайта, только предупреждён
    текстом);
  - поле «Внутренняя заметка» у автомобиля — видно только в админке;
  - файлы: `cars/admin.py`, `cars/models.py`, `config/settings.py`.

- [ ] **Доработка админки (со следующей сессии)** — *Ян*, продолжение
  `feature/admin-usability`
  - [x] Перетаскивание фото: было можно хватать только маленькую
    иконку — теперь можно и само фото, и область вокруг него; фото
    выложены в ряд (сеткой), а не колонкой.
  - [x] Баг: карточка «This item will be deleted. Click to cancel»
    (нажал корзину → предлагает отменить удаление) наезжала на
    соседние фото — вынес её из flex-раскладки карточки в отдельный
    оверлей поверх своей же карточки (`:has(.delete:checked)` в
    `admin-overrides.css`). Отмена проверена — карточка возвращается
    как была.
  - [x] Пропорции фото: было жёсткое `object-fit: cover` в
    альбомную рамку — вертикальные фото с телефона обрезались
    наполовину, нельзя было толком оценить фото при редактировании.
    Заменил на `object-fit: contain` (показывает фото целиком,
    с полосками по краям, если пропорции не альбомные) — это только
    для превью в админке, не влияет на будущую карточку в каталоге
    на сайте (там уже друг сам решит, cover или нет).
  - [x] Видео у автомобиля: одно видео на машину (не несколько, как
    фото), загружается файлом на наш сервер — владелец выбрал этот
    вариант, а не ссылку на YouTube. `Car.video`, mp4/mov/webm, до
    100 МБ (проверено — файлы больше лимита отклоняются). Показывается
    в админке (превью с плеером) и в заглушке страницы автомобиля.
  - [x] Предпросмотр карточки и публикация: владелец выбрал отдельное
    поле `Car.is_published` (не связано со «Статусом»). Новая машина
    по умолчанию черновик — не видна на сайте, пока не опубликована.
    Отдельная зелёная кнопка **«Опубликовать»** рядом с «Сохранить» —
    ставит `is_published=True` и сохраняет, не уходя со страницы.
    Обратное действие («Снять с публикации») — только массовым
    действием из списка машин, отдельной кнопки на самой странице для
    этого нет. Чекбокс в форме убрали по просьбе владельца (2026-09-03)
    — вместо него маленький статус-бейдж «ОПУБЛИКОВАНО»/«ЧЕРНОВИК»
    рядом с кнопками (не редактируется, только показывает состояние).
    **Важно:** поле `is_published` исключено из `CarAdminForm`
    (`exclude`, не просто убрано из fieldset) — иначе обычное
    «Сохранить» без явного действия тихо сбрасывало бы публикацию
    обратно в черновик, как раньше это было с фото.
    «Предпросмотром» стала стандартная кнопка Django-админки
    «Смотреть на сайте» (появилась сама благодаря
    `Car.get_absolute_url`) — перенесена вниз формы и вправо, подальше
    от «Удалить автомобиль» (случайно не перепутать). Проверено:
    обычный посетитель получает 404 на неопубликованную машину,
    залогиненный сотрудник (`is_staff`) видит её с пометкой
    «Черновик»; кнопка «Опубликовать» проверена от клика до записи в
    базу.
  - [x] Плюсик добавления объекта в сайдбаре рядом с названием раздела
    (`templates/admin/app_list.html`) — работает для всех разделов
    (Автомобили, Автосалон, Заявки), не только для машин; кнопка
    «+» в правом верхнем углу страницы осталась и продолжает
    работать, эта — просто более быстрый путь из самого меню.
    Демо-данные (`seed_demo`) публикуются сразу; 16 уже существующих
    машин в базе опубликованы отдельно, чтобы не пропали с сайта
    из-за нового поля.
    **На заметку:** когда будем подключать каталог к базе (следующий
    шаг перед фильтрами), не забыть добавить `is_published=True` в
    фильтр запроса — иначе черновики начнут просачиваться в список.

Параллельно безопасно: разные файлы. После merge обеих веток
подключаем карточки к реальным данным из базы (небольшая задача,
делает любой из двоих; учесть `is_published=True` в запросе — см.
выше).
